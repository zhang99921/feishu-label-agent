扫码入口与四档权限

可管理(full_access) → 管理员；可编辑(edit) → 操作员；可阅读(view) → 查询员。
明确无权限(none) → 拒绝业务访问。未能核实权限 → 503，不猜测角色。
管理员和操作员可查询、入库、出库、转仓；查询员仅查询。
管理权限不代表目前已经提供后台配置、纠错等尚未实现的接口。

启用
在项目 .env 填写 FEISHU_APP_ID、FEISHU_APP_SECRET、FEISHU_APP_TOKEN、
FEISHU_SCAN_TABLE_ID、FEISHU_TENANT_KEY、FEISHU_OAUTH_REDIRECT_URI，
然后设置 FINDING_ASSISTANT_ENABLE_SCAN_API=true，运行 uv run python main.py。
也可保留 FEISHU_BASE_URL 的 Wiki 链接，由已授权应用解析底层 Base。
回调必须登记在飞书开发者后台，路径为 /auth/feishu/callback。
本机示例：http://127.0.0.1:8001/auth/feishu/callback。
应用需具备读取文档协作者的权限；用户授权需包含 auth:user.id:read、bitable:app、offline_access。
不使用旧版 config.local.json、demo_role_policy.json 或自定义角色成员映射。
不要把测试应用的凭据填入正式租户的配置。

接口
GET  /auth/feishu/start                 开始飞书用户授权
GET  /api/v1/access/me                  当前已核实的身份和角色
GET  /api/v1/scans                      查询本人可见的扫码流水；支持 page_token 翻页
POST /api/v1/scans/inbound              入库流水
POST /api/v1/scans/outbound             出库流水
POST /api/v1/scans/transfer             转仓流水
POST /auth/logout                      注销本地会话

写请求体示例：{"fields":{"行码":"P-0001","箱号1":"260929-0008"}}
事件类型由接口固定；也可传同名事件类型，但不能与接口冲突。
每次新提交生成标准 UUID v4 并放入 Idempotency-Key 请求头；重试沿用原值和原数据。
浏览器自动携带 HttpOnly 会话 Cookie；写请求还须将 scan_csrf Cookie
的值放入 X-CSRF-Token 请求头。服务端不向浏览器返回飞书访问令牌。
不得提交操作人、数量、处理状态、处理说明、旧流水号或业务角色。

新流水初始状态（2026-10-23）
入库、出库、兼容转仓和自动分配模式的转仓，均在真正创建飞书记录时由后端固定补充
“处理状态=待处理”；无需客户端提供，不依赖表单默认值。飞书原字段须保留该既有选项。
这表示流水等待接收或处理，不代表箱表变更或库存入账已经完成。
写请求和转仓预占仍保存原业务输入，初始化字段不改变历史请求的幂等摘要。
旧成功请求返回原记录，不重新创建，也不将历史空状态或已完成状态重置为待处理。
遇到RUNNING/UNKNOWN/FAILED仍按既有规则核查，不因本修复重发。
更新后需重启运行中的后端加载代码；无需新增配置、迁移或开启空状态接管。

权限边界
每次操作重新核实登录、租户和直接文档协作者权限，不缓存权限结论。
群组、部门、链接等间接授权尚未解析；未返回直接协作者记录时拒绝放行，
不会把“未核实”当作“明确无权限”，也不会借用应用的权限执行员工操作。
表、字段、行等高级权限由用户令牌调用下的飞书接口继续限制。
因此文档级可编辑并不保证所有表或记录均可写；飞书拒绝时返回403。
应用令牌只用于查询文档协作者，不用于扫码流水读写。
新增接口写入的是扫码流水，不执行库存过账，不回写“已入账”。

启用后的 OAuth 会话和登录挑战保存在 PostgreSQL；有效期内重启可继续使用。
须先设置 FINDING_ASSISTANT_TOKEN_KEY，并执行 uv run python worker.py db-init。
该密钥用于加密访问令牌、刷新令牌和 PKCE verifier，应与数据库分开备份，不能提交 Git。
会话ID、OAuth state、浏览器绑定值只保存摘要。注销会立即撤销会话并清除令牌密文。
新授权会话最长12小时，配置FINDING_ASSISTANT_SESSION_SECONDS=43200；截止时间固定。
访问令牌接近到期时自动刷新，不延长会话截止时间；旧会话需重新授权以取得刷新凭据。
并发与未知刷新结果不重复消耗一次性刷新令牌，详细说明见“登录会话与令牌刷新说明.txt”。
仅四档权限判定仍实时读取飞书，不使用数据库中的旧角色授权。
登录、授权判定和写入结果进入 audit_events；不会记录令牌、授权码或请求头。
write_requests 保留请求正文、摘要、结果及飞书记录ID，供幂等与故障定位。
同键异数据或不同账号会被拒绝；成功重试返回原记录，不再次调用飞书。
RUNNING/UNKNOWN 请求须核实远端结果，不能直接改状态后重发或换键重复提交。
本次不改变飞书字段，仍不能将本地验证视为完整服务器上线验收。
测试文件保留在开发工作区，不复制到运行项目或运行包。

转仓自动模式（2026-10-22）
POST /api/v1/scans/transfer可传target_warehouse选择目标仓，fields提交箱号。
自动预占需显式开启FINDING_ASSISTANT_ENABLE_TRANSFER_ALLOCATION并完成业务读取交接；
现有完整读取只核实管理身份，普通可编辑账号完整范围未确认时返回503。
不因此改变四档权限映射或给操作员扩大管理权限；详情见转仓开发与字段说明.txt。

鉴权调用优化（2026-10-27，当前口径）
普通提交请求从本地持久会话取得已验证身份，并检查注销、绝对过期、访问令牌有效性；需要时仍按原锁机制续期。登录12小时期限不延长，刷新结果未知仍要求重新登录。
飞书四档权限保持当前请求查询，不做跨请求或12小时角色缓存；单次请求内按账号、会话及访问令牌复用成功权限，每个动作继续独立检查及审计。缓存期间发生本地注销/过期，下一次授权调用立即拒绝。
真正开始库存执行时明确复核一次远端身份；排队工作线程使用新作用域，不继承提交时的验证结果。SQL库存读取及进度读取也保留远端身份复核，避免纯SQL读取绕过账号失效检查；行/字段可见范围、原生权限和SQL普通账号开关不变。
登录身份变化或远端明确拒绝时撤销本地会话；远端临时不可用时敏感操作仍拒绝，不借用旧权限放行。令牌续期后的身份绑定校验继续保留。
