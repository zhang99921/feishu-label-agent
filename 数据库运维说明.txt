数据库用途
飞书继续承载现有扫码流水和业务流转。PostgreSQL保存后端辅助数据，以及版本化业务副本/SQL索引。
本机数据库 finding_assistant schema 共19张表（7份迁移）：
scan_jobs：来源任务、幂等摘要和隔离状态。
scan_items：任务的逐箱输入。
scan_job_events：接收任务的状态事件。
app_users：经过飞书核实的应用/租户/账号及登录时间，不维护角色成员。
user_sessions：会话摘要、加密访问/刷新令牌、分别的到期时间、刷新认领和撤销时间。
oauth_challenges：一次性登录state摘要、浏览器绑定摘要、加密PKCE及有效期。
write_requests：前端写请求、输入摘要、调用状态、远端记录ID及响应。
audit_events：登录、注销、授权、写入、重放和维护事件。
location_reservations：转仓来源、目标行码预占、稳定输入及未知结果占用；不是库存主表。
schema_migrations：已执行的迁移文件、SHA-256及执行时间。

配置
数据库连接串由 FINDING_ASSISTANT_DATABASE_URL 指定。
FINDING_ASSISTANT_TOKEN_KEY 必须是随机 Fernet 密钥；运行项目的 .env 已设置本机值。
.env 不提交Git。移到服务器时单独配置该密钥；不要直接更换仍在使用的密钥。
数据库备份与密钥均需保管，失去密钥会导致现存会话无法解密。
不同应用通过 app_id 隔离会话与请求，令牌不明文存入数据库。
账号可能在不同应用具有不同 open_id，因此以应用+租户+open_id识别用户。

命令（在项目目录执行）
uv run python worker.py db-init
  显式执行迁移，可重复运行；校验已经执行的文件摘要，禁止直接修改已上线迁移。
uv run python worker.py status
  返回后台任务、身份运维表和写请求状态的汇总，不输出秘密。
uv run python worker.py doctor
  只读检查配置、数据库连接、七份迁移是否齐全及校验和是否一致，不自动执行迁移。
uv run python worker.py db-maintain
  默认每轮每类最多清理1000条过期挑战、过期超过7天的会话，默认不删除审计。
  审计期限尚未确认；仅另行确定期限后显式传--audit-days才会分批清理到期审计。
  该命令不会自动运行；不要将运行日志30天期限套用到审计或未经确认安排审计清理。
  不清理用户、后台任务和写请求，避免丢失业务追踪或幂等依据。

异常处理
PENDING：尚未开始外部写入。
RUNNING：已开始调用；长时间停留时应核实远端记录和日志。
SUCCEEDED：流水已写入，可按记录ID查询；不代表库存完成入账。
FAILED：飞书明确拒绝；检查账号和表/字段权限。
UNKNOWN：结果不确定，禁止自动重发，人工核对后再设计补偿处理。
接口超时、上游响应无法核实等异常同样保留UNKNOWN，不因异常继承关系误标为FAILED。
当前不提供一键改状态/强制重试接口，避免误操作产生重复流水。

日常关注 write_requests 的 UNKNOWN/RUNNING 积压、任务 BLOCKED/RECONCILE、
数据库磁盘容量、备份是否成功。定期备份 PostgreSQL 并验证恢复。
本地已验证事务与重启后会话恢复；尚未代替服务器备份、监控和全天运行验收。

轮询式增量同步（2026-10-26）
入口仍为worker.py sync --watch，单worker串行处理，飞书保持业务主存。
FINDING_ASSISTANT_ENABLE_INCREMENTAL_SYNC=true启用；运行模板默认false，本机固定Demo已配置true。
FEISHU_SYNC_FULL_SECONDS=3600：第一轮建立全量基线，之后每轮轮询增量，到期再执行所有表业务字段全量对账。
周期按实际同步轮次触发，关机/停止时不运行，不是精确整点计划；独立的周期SQL内容巡检仍保持3600秒。

实现方式是分页读取完整记录ID/系统修改时间/主字段清单，再回读变化记录；不是公网事件推送，不需要新增公网回调或订阅权限。
删除通过确认后的完整ID清单识别，不把单条接口404、网络错误或缺页推断为删除。
清单前后两次核对；变化、缺少时间、结构不稳或单条回读不确定时放弃本轮暂存，改用全量读取。
若只是分页顺序变化也保守回退；大批变更超过100次单条回读预算同样回退，避免过多请求。
纯数据类型才复用缓存；当前支持类型1/2/3/4/5/7/13/15/1005。关联、公式、查找、附件、人员和未知字段的表每轮仍全读。
不额外增加飞书字段，不依赖使用者创建“最后修改时间”业务列；用接口automatic_fields返回的系统元数据。
缓存原始内容先与已发布摘要核对，损坏时从源全读并发布新版本，保留原有历史版本，不原地篡改历史业务字段。
技术时间戳不是跨表事务版本；源未改变时间或同一时间精度内的遗漏，仍需周期全量对账兜底，不宣称源端ACID快照。

仍将完整当前记录集写入未发布SQL版本，校验并重建箱索引后原子切换active_backup_id。
源的行表变更会反映到重建的箱索引。原始字段不变时复用活动版本，仅刷新独立技术时间，不积累重复完整版本。
每页最多100条；不把整个表或完整ID集合放入Python内存。当前优化的是飞书正文回读，SQL仍有完整暂存、摘要和索引开销。
每轮仍需扫描全部ID清单且存在额外请求；小样本不保证比全量更快，正式数据规模须测网络耗时、限流和磁盘I/O。

源修改时间与业务fields分开存储，不改已有字段设计；后台仍21张表，迁移总数10份，001至009校验和保持不变。
