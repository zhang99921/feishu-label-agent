飞书同步与PostgreSQL检索说明

日期：2026-10-23



一、数据职责

飞书仍为当前业务主存。PostgreSQL保存各表结构、原始字段JSONB、箱检索索引以及日常查询版本。

扫描写入和库存执行不因启用SQL检索而改为SQL主存；库存操作仍核实飞书当前状态，不能用延迟副本代替防重校验。

正式仓库表只读。本机已授权Demo使用固定14张表，不再新增重复测试表。

公式/查找引用按飞书返回值保存，不代表已在SQL重建公式引擎；附件引用不等于附件实体备份。



二、同步配置与启动

在.env中配置凭据、Base、扫码表、数据库连接；密钥不写源码，也不提交或打包。

FEISHU_SYNC_TABLE_IDS：英文逗号分隔的明确表ID清单，必须覆盖箱表关联的行表；不默认读取整个Base。

FEISHU_SYNC_SECONDS=60：一轮完整拉取结束后再等待60秒，不是承诺数据最多延迟60秒。

FINDING_ASSISTANT_SQL_STALE_SECONDS=300：从最近成功一轮的读取开始时间计算数据年龄，超过300秒显示stale。

FINDING_ASSISTANT_ENABLE_SQL_QUERY=true：HTTP装配和find-boxes使用已发布的日常SQL副本。

首次安装新迁移：.\.venv\Scripts\python.exe worker.py db-init

仅同步一轮：.\.venv\Scripts\python.exe worker.py sync

持续同步：.\.venv\Scripts\python.exe worker.py sync --watch

查看状态：.\.venv\Scripts\python.exe worker.py sync-status

停止前台worker：Ctrl+C。HTTP与同步worker是两个常驻进程；只启动main.py不会自动拉起worker。

服务器进程托管、开机启动和长期运行验收仍需部署阶段配置，不依赖Codex会话维持运行。

所有命令支持--env-file；进程的环境变量优先于配置文件。



三、直接SQL查询

.\.venv\Scripts\python.exe worker.py find-boxes --box-code 260929-0008

可组合--fnsku、--sku、--po、--row-code、--position-code=-01、--state、--limit、--offset。

全部筛选由参数化SQL执行，不先拉飞书全表到内存过滤。

.\.venv\Scripts\python.exe worker.py replica-records --table-id <已配置表ID> --limit 20

原始记录按record_id分页，下一页使用--after-id；各页需核对返回版本ID，版本切换时重新分页。

数量以十进制字符串返回；同箱号多个档案保留多条，不擅自取第一条。

没有完整已发布副本或配置表范围变化时返回未就绪，不回退到飞书逐次读取业务表。



四、登录查询接口与可见范围

GET /api/v1/search/boxes?box_code=260929-0008

GET /api/v1/sync/status

复用现有飞书登录Cookie或后端不透明Bearer会话。客户端不能指定任意Base、表或操作人。

业务数据来自SQL；每次请求仍须核实登录和飞书当前权限，权限服务故障时拒绝请求。

用户已确定保留飞书逐行、逐字段可见范围，不能把应用拉取的完整副本开放给所有可编辑/可阅读账号。

目前这两个新接口仅对可管理账号开放；可编辑/可阅读账号在行列范围同步与验收完成前返回403。

此限制不改变原有扫码接口的四档权限映射，也不声称普通账号的SQL查询已经完成。

后续须同步可见记录/字段范围、权限变更与失效机制，并用不同实际账号验收；见T014。

本机Demo配置使用已登记的回调8765端口，HTTP启动：.\.venv\Scripts\python.exe main.py --port 8765

先访问/auth/feishu/start完成登录，再调用检索接口。HTTP默认8001不等于OAuth回调已自动修改。



五、一致性、恢复与运维

按Base使用数据库会话锁，同一来源不会被两个worker并行发布。

每轮完整读取选定表并校验结构/关联，保存原始字段与箱索引后原子切换active_backup_id。

上游失败、关联不完整或中断保留上一完整版本；首次失败没有可查询数据。失败日志不记录凭据和原始业务内容。

同步失败退避重试；进程崩溃后数据库释放锁，新worker可继续，不删除旧审计或业务执行数据。

源删除记录在下次完整成功版本中消失；不会清除历史备份。

内容未变只更新时间，不重复保存全量版本；真正变化才增加完整版本。

当前采用全量轮询，尚未接入增量事件。数据量增长后需补增量对账及同步版本保留策略，历史版本不自动删除。

查询结果包含ready、sync、data_age_seconds、stale和读取起止时间。失败可继续检索旧数据，但必须保留过期提示。

飞书读取跨多次HTTP调用，不具有远端跨表ACID快照保证；单轮内的并发修改仍可能需要下一轮或人工对账。

业务主存迁移、附件实体、公式等价实现、普通账号ACL和服务器长期验收均不因本功能启用而自动完成。

分页同步与副本存储巡检（2026-10-23）
日常worker.py sync改为每页最多100条记录暂存至PostgreSQL，随后用服务端游标分批计算摘要和建立箱索引。
内存不再同时保留所有表记录或整张行表映射；单条记录大小、字段元数据和数据库自身资源仍影响实际占用。
所有配置内的表读完、字段前后复核一致、关联与数值校验通过后，才切换active_backup_id。
暂存阶段日常查询继续使用旧完整版本；失败不发布半成品，清理自己本轮未发布的暂存行并保留失败头。
中断遗留的本实现RUNNING暂存仅在下轮取得同一Base同步锁后回收；人工归档和已完成版本不在自动清理范围。
内容未变时删除本轮未发布暂存并刷新检查时间，不新增永久完整版本。
摘要算法升级首次生成一个新完整版本，后续相同内容复用；原版本继续保留。
仍是完整分页轮询，不是增量同步，也不是飞书跨表ACID快照。同步间隔仍为一轮结束后60秒。
日志增加耗时、记录数、记录页数和最大页条数，不写入业务原文、令牌或连接串。

运维命令（在项目根目录执行；只读SQL，不访问飞书）：
  uv run python worker.py backup-storage
  uv run python worker.py backup-prune-preview --keep-days 30 --keep-latest 2
第二条仅演示预览参数，未将30天或2个版本设为正式保留策略。参数必须显式提供。
preview返回候选数量和分页版本清单，deletion_executed始终为false；本次未提供历史版本删除入口。
预览限定当前Base、相同同步表范围的成功日常副本，保留活动查询版本、权限依据引用、最近N个版本、显式保护版本及人工归档。
其他Base/范围、失败或进行中版本不作为预览候选；保护标记为metadata的protected/pinned/retain=true或retention=keep。
backup-storage区分当前Base记录逻辑体积与全部Base共用表/索引的物理体积；统计有10秒超时，数据量过大应另行安排巡检。
暂存写入与删除仍产生数据库I/O和可重用空闲页；删除不会立即缩小PostgreSQL磁盘文件，需要数据库常规autovacuum维护。

SQL副本完整性巡检（2026-10-26）
运行入口：uv run python worker.py replica-check
在同一只读数据库快照内固定active_backup_id，核对已配置表范围、版本头表数/记录数与实际数据、箱索引覆盖数量。
健康返回healthy=true及退出码0；没有完整活动版本或发现不一致返回healthy=false、固定问题码及退出码2。
数据库不可用等命令执行故障按既有通用错误路径返回非0，不打印连接串或原始异常。
巡检仅返回版本、计数、问题码，不回传箱数据或身份凭据；不写数据库、不修复、不删除，也不访问飞书。
健康仅表示上述SQL结构检查通过，不代表字段内容逐值一致、同步新鲜度合格或飞书源与SQL实时一致。
数据时效另看worker.py sync-status；完整源读取和内容摘要由持续同步负责，源数据仍有分页读取窗口。
无需新增迁移或修改.env；普通账号行列权限开关不变。当前后台21张表、9份迁移。

轮询式增量同步（2026-10-26）
入口仍为worker.py sync --watch，单worker串行处理，飞书保持业务主存。
FINDING_ASSISTANT_ENABLE_INCREMENTAL_SYNC=true启用；运行模板默认false，本机固定Demo已配置true。
FEISHU_SYNC_FULL_SECONDS=3600：第一轮建立全量基线，之后每轮轮询增量，到期再执行所有表业务字段全量对账。
周期按实际同步轮次触发，关机/停止时不运行，不是精确整点计划；独立的周期SQL内容巡检仍保持3600秒。

实现方式是分页读取完整记录ID/系统修改时间/主字段清单，再回读变化记录；不是公网事件推送，不需要新增公网回调或订阅权限。
删除通过确认后的完整ID清单识别，不把单条接口404、网络错误或缺页推断为删除。
清单前后两次核对；变化、缺少时间、结构不稳或单条回读不确定时放弃本轮暂存，改用全量读取。
若只是分页顺序变化也保守回退；大批变更超过100次单条回读预算同样回退，避免过多请求。
纯数据类型才复用缓存；当前支持类型1/2/3/4/5/7/13/15/1005。关联、公式、查找、附件、人员和未知字段的表每轮仍全读。
不额外增加飞书字段，不依赖使用者创建“最后修改时间”业务列；用接口automatic_fields返回的系统元数据。
缓存原始内容先与已发布摘要核对，损坏时从源全读并发布新版本，保留原有历史版本，不原地篡改历史业务字段。
