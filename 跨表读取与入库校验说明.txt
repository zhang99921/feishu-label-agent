跨表只读读取与入库校验
更新日期：2026-10-22

已开发范围
1. 箱表：按箱号精确检索，读取箱号、状态和“行”关联。
2. 行表：按行码精确检索，读取行码与所属仓库。
3. 事务账：按明确的“单据引用”精确检索，读取箱号/行、类型、行、变更前及变更后。
   不假定该文本字段唯一，不把旧单据引用自动解释为来源流水record_id。
4. 读取字段元数据，验证字段类型及箱表“行”关联的目标表。
5. 完成全部分页再判断结果，保留重复箱档案；相同源记录分页重叠可去重，
   同一源记录内容中途变化则停止判断。未使用带筛选条件的视图作为完整查询依据。
6. 只读入库预览接入已有规则及已确认的位置冲突、所选仓库匹配规则。

接口
POST /api/v1/scans/inbound/validate
请求示例：
{"box_codes":["260929-0008"],"location_code":"Q-001","warehouse":"欣源仓"}
以上只是请求格式，不代表示例箱号和行码当前可入库。
使用现有后端会话鉴权；浏览器Cookie调用同样需要 X-CSRF-Token。
不需要写入幂等键，因为本接口不创建或修改业务记录。

结果
HTTP 200 + READY：相关数据完整读取，当前已确认规则未发现异常；不代表已经入账。
HTTP 200 + BLOCKED：存在业务异常，整批可处理箱号为空，列出箱号及原因。
HTTP 503 + BUSINESS_VALIDATION_UNAVAILABLE：查询或完整可见范围无法核实，
  不能把它解释成箱号不存在，也不能继续入账。
HTTP 403：角色或飞书接口拒绝访问。
HTTP 401：未登录或身份授权失效。
HTTP 422：请求格式错误。
返回 feedback_suggestion 仅为将来的异常回写建议，不会实际写入处理状态。

配置
FEISHU_BOX_TABLE_ID：现有箱表ID。
FEISHU_ROW_TABLE_ID：现有行表ID。
FEISHU_TRANSACTION_TABLE_ID：事务账ID，可暂不填；只读事务查询时必须配置。
箱表和行表必须同时配置，且不能与扫码流水表混用。
三个ID属于已配置的同一个Base，不能把不同租户或不同Base的ID混用。
配置留空时不启用跨表读取，不在代码中硬编码正式表或Demo表ID。
真实租户App ID、Secret、URL、Base token继续只从 .env/环境读取。

身份与权限限制
本版读取沿用已登录用户令牌，不借用应用令牌扩大可见范围。
初期只允许可核实为文档“可管理”的账号执行完整性判断。
可编辑账号可能被高级权限隐藏部分行，空结果不能证明箱号不存在，因此返回未核实。
普通操作员的完整后台读取身份、授权范围和返回内容边界仍列入待定事项P018。
同一请求中任何表读取失败，都不返回“校验通过”，不使用旧缓存替代当前状态。
跨表读取没有事务快照保证；将来实际执行入账前仍需并发控制与状态复核。

与当前写入入口的关系
这是独立的只读预览入口，尚未强制挂到原 POST /api/v1/scans/inbound 写入前。
原因：已确认提交先生成待处理流水，而行码分配、库存执行及异常结果回写尚未开发。
本次不执行库存入账、不分配行码、不增加事务、不修改飞书字段或创建新表。
原入库提交接口仍属于表单数据写入，不能当作已完成全部跨表校验的入账接口。
事务账查询已准备好供后续恢复模块调用，尚未执行“已有事务就跳过入账”等新策略。
数量、返库、半箱、SKU完整性等未敲定规则未增加拦截。

当前验证
已用自动化模拟HTTP覆盖查询格式、分页、权限、字段与重复档案、业务规则和预览路由。
已用用户提供的仓库库存信息.base，经同一字段映射/HTTP契约模拟层验证真实导出结构：
箱表9107条、行表59条、事务账7750条；验证待入库箱预览、整批阻断及事务引用读取。
上述为导出数据的离线验证，不是正式飞书实时接口验收。
正式跨表实时读取仍需同租户授权配置及真实账号验收。
测试脚本和结果只保留在开发工作区，不复制到E盘运行项目。

RX02：入库入口接收已有在库/在托的完整可跟踪批次，自动分配不同目标行；流水仍为入库，来源区域记录原行码，逐箱事务类型记转行。
完成后箱状态统一在库，首次入库时间保持原值；批次ID沿用，原位置核账后冷却10分钟。独立转仓入口原行为保留。
原行重复扫规则仍未定：自动转行不分配原行；目标仓无其他可核实区域时拒绝，不将同一行换位置解释为已确认转行。
只支持现有完整来源批次；待入库箱与转行箱分单，部分转仓和无后台占用的历史箱仍不自动接管。
RX04：已存在有效档案、状态允许且通过当前数量校验的半箱可入库、正常出库或待入库直接出库；直接出库事务注明未经入库直接出库。
Q-尾数按行表中有效区域处理，但不是半箱的强制唯一目的地；不新增区域，不按名称猜仓库。
本次不开发半箱绑定/发号工作流，不放行空号、待清点、作废，不敲定数量/商品缺失等其他规则。
基础入库预览只判断已有读取范围中的规则；预览READY不代替来源位置、后台占用、全批成员及执行前的完整校验。
现有同键幂等、权限、未知结果核实、审计、逐箱事务及完成后冷却保护保留；自动转行新增来源变化的整批异常反馈。
无需数据库迁移，不改.env或日常业务开关，不修改正式表、Demo字段及业务记录。新HTTP进程加载；现有HTTP需重启，SQL同步worker无需重启。
算法结果表尚未接入，当前仍沿用本地分配器；此项不等于已完成算法对接。普通人员、扫码硬件及真实Demo旧规则专项验收继续待办。
