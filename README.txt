一、交付内容

提供干净运行目录、同内容ZIP压缩包，以及ZIP的.sha256文件。
运行目录包含finding_assistant源码、main.py、worker.py、pyproject.toml、uv.lock、
空敏感项的.env.example、必要操作说明、待办与业务基线，以及runtime-manifest.json。
不包含测试用例、验证脚本、报告、模拟数据、真实.env、会话、日志、虚拟环境、
IDE配置、Git元数据和旧根目录兼容包装。
运行模块中保留必要的历史实现依赖和未来MCP适配，当前运行入口不会自动启用它们。

打包工具留在开发侧，不放入运行项目；使用固定文件清单，不整目录复制。
新增运行模块必须更新清单，静态本地导入检查用于发现已导入但漏列的新模块。
模板中的敏感项保持空值，只允许已登记的非敏感默认值；不读取真实.env来生成包。
输出位置必须在源码目录之外，已有目录、ZIP或校验文件均不会被覆盖。
runtime-manifest.json记录每个交付文件的字节数、SHA-256和构建编号；
同一源码、同一build_id生成一致的ZIP内容，构建期间源码变化则停止交付。
文件校验用于核对交付完整性，不代表人员权限、业务流程或目标服务器已经验收。

二、目标主机准备与启动

1. 将ZIP解压到新的项目目录；包内文件直接位于ZIP根部，不混入旧目录的运行状态。
   首次使用时以.env.example建立本机.env；已有配置单独保留，不用模板覆盖真实配置。
2. 准备Python 3.12和uv，在项目目录执行：
     uv sync --python 3.12 --locked --no-dev
   此步骤按uv.lock在目标主机重建环境，不复制本机.venv；依赖需能从锁文件的源获取。
3. 由维护人员填写.env的应用、Base/流水表、租户、OAuth回调、数据库及加密密钥。
   默认FINDING_ASSISTANT_ENABLE_SCAN_API=false；配置HTTP_ONLY检查通过只表示基础模式可启动。
4. 配置自检：
     uv run --no-sync python main.py --check-config
   数据库诊断：
     uv run --no-sync python worker.py doctor
   新环境的数据库迁移由维护人员显式执行worker.py db-init，启动时不会自动建表。
5. 启动HTTP服务：
     uv run --no-sync python main.py
   默认127.0.0.1:8001。监听地址、域名HTTPS、OAuth回调和服务器托管方式在部署时配置。
   当前步骤不自动开启端口对外访问，也不自动建立系统服务。
6. 后台接收与HTTP是不同进程；已有流水接管范围、应用授权及交接具备后，再按需运行：
     uv run --no-sync python worker.py poll --watch
   当前只接收内部任务，不执行库存过账，不替换旧处理程序。

真实密钥通过本机.env或部署环境单独配置，不写入源码、压缩包、日志或待办文件。
文件内容修改、依赖更新后应重新构建新快照，不修改清单哈希来将旧包冒充新包。

代码回退不自动回退数据库迁移；既有迁移的内容和校验和不能直接修改。
新旧进程不并行处理同一来源流水，不把换目录理解为已经完成旧程序停用和任务接管。
本轮不执行上线、远程推送、版本发布或数据库切换。

分页同步与副本存储巡检（2026-10-23）
日常worker.py sync改为每页最多100条记录暂存至PostgreSQL，随后用服务端游标分批计算摘要和建立箱索引。
内存不再同时保留所有表记录或整张行表映射；单条记录大小、字段元数据和数据库自身资源仍影响实际占用。
所有配置内的表读完、字段前后复核一致、关联与数值校验通过后，才切换active_backup_id。
暂存阶段日常查询继续使用旧完整版本；失败不发布半成品，清理自己本轮未发布的暂存行并保留失败头。
中断遗留的本实现RUNNING暂存仅在下轮取得同一Base同步锁后回收；人工归档和已完成版本不在自动清理范围。
内容未变时删除本轮未发布暂存并刷新检查时间，不新增永久完整版本。
摘要算法升级首次生成一个新完整版本，后续相同内容复用；原版本继续保留。
仍是完整分页轮询，不是增量同步，也不是飞书跨表ACID快照。同步间隔仍为一轮结束后60秒。
日志增加耗时、记录数、记录页数和最大页条数，不写入业务原文、令牌或连接串。

运维命令（在项目根目录执行；只读SQL，不访问飞书）：
  uv run python worker.py backup-storage
  uv run python worker.py backup-prune-preview --keep-days 30 --keep-latest 2
第二条仅演示预览参数，未将30天或2个版本设为正式保留策略。参数必须显式提供。
preview返回候选数量和分页版本清单，deletion_executed始终为false；本次未提供历史版本删除入口。
预览限定当前Base、相同同步表范围的成功日常副本，保留活动查询版本、权限依据引用、最近N个版本、显式保护版本及人工归档。
其他Base/范围、失败或进行中版本不作为预览候选；保护标记为metadata的protected/pinned/retain=true或retention=keep。
backup-storage区分当前Base记录逻辑体积与全部Base共用表/索引的物理体积；统计有10秒超时，数据量过大应另行安排巡检。
暂存写入与删除仍产生数据库I/O和可重用空闲页；删除不会立即缩小PostgreSQL磁盘文件，需要数据库常规autovacuum维护。

本次复用现有21张后台表与9份迁移，无需新增建表或修改已安装迁移。
正式源表保持只读；普通账号SQL行列范围开关保持关闭，原库存执行和位置分配开关不变。
T015仍包含正式数据规模/限流与耗时评估、增量方案、保留期限/存储告警和服务器长期运行验收；此次不将其整体标为完成。

SQL副本完整性巡检（2026-10-26）
运行入口：uv run python worker.py replica-check
在同一只读数据库快照内固定active_backup_id，核对已配置表范围、版本头表数/记录数与实际数据、箱索引覆盖数量。
健康返回healthy=true及退出码0；没有完整活动版本或发现不一致返回healthy=false、固定问题码及退出码2。
数据库不可用等命令执行故障按既有通用错误路径返回非0，不打印连接串或原始异常。
巡检仅返回版本、计数、问题码，不回传箱数据或身份凭据；不写数据库、不修复、不删除，也不访问飞书。
健康仅表示上述SQL结构检查通过，不代表字段内容逐值一致、同步新鲜度合格或飞书源与SQL实时一致。
数据时效另看worker.py sync-status；完整源读取和内容摘要由持续同步负责，源数据仍有分页读取窗口。
无需新增迁移或修改.env；普通账号行列权限开关不变。当前后台21张表、9份迁移。
T015中SQL活动副本基础完整性巡检已实现；增量事件、正式数据量压测、保留策略及目标服务器长期验收仍待办。
发现异常先保留证据并排查，不自动清空任务、重发请求或改写飞书。测试材料仅保存在开发目录。


SQL副本内容核验（2026-10-26）
运行入口：uv run python worker.py replica-check --verify-content
在基础结构检查之外，同一只读数据库快照内重新计算原始字段及表结构/名称的内容摘要，并逐页核对箱索引值。
核对箱号、FNSKU、SKU、PO、状态、数量、行码、位置码、仓库及真实关联表/记录ID，十进制数量保持精度。
每批最多100条，不把全部箱索引加载到内存；检查较基础巡检耗时更高，正式规模须另行实测。
兼容当前摘要版本2，摘要算法及原有版本标识未改变，因此升级不应单独引起业务副本重新发布。
旧摘要版本不能验证时返回REPLICA_DIGEST_VERSION_UNSUPPORTED及非0退出码，不伪称完整核验通过。
内容改变或索引偏差返回固定问题码和差异数量，退出码2；不输出箱号/字段值，不自动修复或覆盖数据。
只读查询受原有SQL语句超时保护；执行失败按非0错误处理，不能当作核验通过。
该命令验证SQL版本内部一致性，不访问飞书，不代表源与SQL实时一致；新鲜度仍查看sync-status。
原基础replica-check命令保留。既有后台迁移、.env、权限开关及同步间隔均不变。
本次仅复用同一摘要实现供只读检查；后台同步算法未变，已运行的worker不需要为此重启。
T015的SQL内容及箱索引一致性核验已开发；增量事件、周期调度、正式数据量压测、保留策略仍待办。

后台周期内容巡检（2026-10-26）
运行入口仍为uv run python worker.py sync --watch，不另开worker或额外定时器。
配置FINDING_ASSISTANT_REPLICA_CHECK_SECONDS：0关闭；正整数60至604800秒，3600表示一小时。
运行包模板默认0，本机Demo配置为3600；服务器部署时按规模评估后填写.env。
启用后启动的第一轮同步结束即检查，此后从巡检完成时计时，达到间隔后的下一个同步轮次执行。
实际间隔受同步轮次、失败退避和检查耗时影响，不保证严格整点或精确每3600秒执行。
巡检与同步串行，不重叠；抢不到Base同步锁的BUSY轮不再巡检。停止标记到达后不启动新检查。
进程重启会再检查一次，不补跑离线期间的历史时段；单次sync也会在本轮结束后执行一次已启用的检查。
日志replica_check=HEALTHY表示SQL内容/索引核验通过；INCONSISTENT表示差异，UNAVAILABLE表示执行故障。
记录失败不会篡改已成功的同步结果，不中止watch，也不改变原同步失败退避；不自动修复、清理或写入飞书。
同步失败时仍可检查旧SQL版本；HEALTHY不代表源读取成功或数据新鲜，时效另查看sync-status。
日志不写任意问题原文、箱数据或异常堆栈；详细固定问题码使用replica-check --verify-content人工读取。
沿用sync.log轮转和原SQL语句超时，未新增数据库表、迁移、飞书权限或外部通知渠道。
本项完成进程内周期核验调度，不代表服务器自启、跨重启历史调度台账或长期运行验收完成。
增量事件、正式规模压测、版本保留与存储告警仍按T015保留；测试材料不交付运行目录。


轮询式增量同步（2026-10-26）
入口仍为worker.py sync --watch，单worker串行处理，飞书保持业务主存。
FINDING_ASSISTANT_ENABLE_INCREMENTAL_SYNC=true启用；运行模板默认false，本机固定Demo已配置true。
FEISHU_SYNC_FULL_SECONDS=3600：第一轮建立全量基线，之后每轮轮询增量，到期再执行所有表业务字段全量对账。
周期按实际同步轮次触发，关机/停止时不运行，不是精确整点计划；独立的周期SQL内容巡检仍保持3600秒。

实现方式是分页读取完整记录ID/系统修改时间/主字段清单，再回读变化记录；不是公网事件推送，不需要新增公网回调或订阅权限。
删除通过确认后的完整ID清单识别，不把单条接口404、网络错误或缺页推断为删除。
清单前后两次核对；变化、缺少时间、结构不稳或单条回读不确定时放弃本轮暂存，改用全量读取。
若只是分页顺序变化也保守回退；大批变更超过100次单条回读预算同样回退，避免过多请求。
纯数据类型才复用缓存；当前支持类型1/2/3/4/5/7/13/15/1005。关联、公式、查找、附件、人员和未知字段的表每轮仍全读。
不额外增加飞书字段，不依赖使用者创建“最后修改时间”业务列；用接口automatic_fields返回的系统元数据。
缓存原始内容先与已发布摘要核对，损坏时从源全读并发布新版本，保留原有历史版本，不原地篡改历史业务字段。
技术时间戳不是跨表事务版本；源未改变时间或同一时间精度内的遗漏，仍需周期全量对账兜底，不宣称源端ACID快照。

仍将完整当前记录集写入未发布SQL版本，校验并重建箱索引后原子切换active_backup_id。
源的行表变更会反映到重建的箱索引。原始字段不变时复用活动版本，仅刷新独立技术时间，不积累重复完整版本。
每页最多100条；不把整个表或完整ID集合放入Python内存。当前优化的是飞书正文回读，SQL仍有完整暂存、摘要和索引开销。
每轮仍需扫描全部ID清单且存在额外请求；小样本不保证比全量更快，正式数据规模须测网络耗时、限流和磁盘I/O。

使用与恢复
首次登录点击飞书登录；带ui=true的登录仅返回固定/app，既有API登录默认返回身份接口。不会接受任意外部返回地址。
每次写入仍由服务端校验身份和权限；界面禁用仅是交互提示，不代替后端鉴权。当前完整库存读取仍要求已验证的管理范围。
确认前分配并保存UUID请求键，确认后任何重试沿用原键。提交结果未知时只能手动使用原请求继续，不自动生成新键。
拿到流水record_id后，受理后台执行，再按5秒周期查询原任务；网络故障只重试进度读取，不自动重发库存写入。
202或流水创建不等于入账完成，只有SUCCEEDED且inventory_posted=true才显示全部完成。
服务重启后有已持久化计划但未调度时，用户可明确继续处理原流水；未知写入/RECONCILE必须核查，不提供强制覆盖或释放。
草稿和恢复指针保存在当前标签页sessionStorage，包含当前账号、箱号、仓库和原请求键，不保存OAuth令牌或密钥。
同一标签页刷新可恢复；不同账号不可恢复原账号状态。草稿12小时过期；已提交未完成任务不因重新登录自动换键。
关闭标签页或清除浏览器数据后，跨设备/新标签页自动找回尚未实现；需通过原流水和运维接口定位，不能宣称所有断线恢复已完成。
退出登录清除当前标签页恢复数据；浏览器无法保存时阻止首次提交。此存储不能替代数据库持久账本。
