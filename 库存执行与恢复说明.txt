库存执行与恢复说明
更新日期：2026-10-23

当前交付边界
已新增统一库存执行器，供已登录用户处理本人已登记的扫码流水。
入库、转仓、出库使用同一套不可变计划、逐箱事务、步骤回读和完成确认流程。
实际执行默认关闭；本轮只用隔离PostgreSQL和模拟飞书HTTP验证，没有向正式表或Demo写库存。
普通操作员完整跨表读取、后台应用代执行身份、原生表单的自动位置预占、历史批次接管仍待完成。
本模块不自动启动后台过账定时任务，不停止旧程序，不将旧表单提交直接视为库存已变更。

一、配置和启用条件
默认 FINDING_ASSISTANT_ENABLE_INVENTORY_EXECUTION=false。
显式启用时还须启用扫码API及组合位置分配，并配置：
FEISHU_BOX_TABLE_ID、FEISHU_ROW_TABLE_ID、FEISHU_TRANSACTION_TABLE_ID、FEISHU_BOX_DETAILS_TABLE_ID。
FEISHU_SCAN_TABLE_ID 必须指向实际扫码流水表；样本复制时物化成文本的创建人字段不可代用。
所有配置通过.env提供，不把应用凭据、表ID或用户令牌写死在代码里。
数据库先执行 worker.py db-init；启动只检查迁移和校验和，不自动改结构。
启用前须另行完成真实账号、表字段权限、单选选项、外部写入者停用及人工核账验收。
飞书仍是业务库存主存，PostgreSQL保存执行凭据、后端控制和独立业务副本。

二、接口
POST /api/v1/inventory-executions/{record_id}/prepare：读取本人流水，整批校验并冻结计划，不写库存。
POST /api/v1/inventory-executions/{record_id}/execute：执行原计划或核实中断后的原步骤。
GET /api/v1/inventory-executions/{record_id}：查询执行进度和固定原因码。
沿用既有Bearer会话，或Cookie会话加POST的CSRF校验；不接收外部传入的用户、角色或执行计划。
这里record_id是扫码流水的飞书内部ID。业务幂等身份为Base:扫码表:record_id，重复调用沿用同一计划。
创建流水入口仍使用UUID4 Idempotency-Key；创建流水和执行库存是两个独立阶段。
创建接口继续返回inventory_posted=false；执行接口仅在全部步骤和位置确认完成后返回true。
本轮采用当前用户令牌且仅允许操作本人创建的流水；没有扩大应用身份替其他用户写入。
当前完整读取保护仍只通过可管理账号；可编辑用户的完整跨表范围未核实，不能宣称已验收可用。

三、正常分支
入库：沿用箱档案，更新在库、行关联及位置码；入库时间首次填写，已有时间保留。
转仓：沿用同一批次ID，修改行和位置码；保留状态、数量和首次入库时间。
事务账按原仓/目标仓决定转行或转仓；来源区域保留原行码。
出库：箱状态改已出库，清空当前行关联和位置码；本箱套数及入库时间保留。
对应箱明细按文本箱号匹配，当前套数置0、状态已拣空；待入库无位置可走直接出库分支。
已出库且位置为空的箱子只作忽略，记录忽略数量，不新增事务账；其他未完成操作仍会阻止新操作。
每个实际处理箱子对应一条后端事务及一条飞书事务账，数量读取箱档案本箱套数，不取扫码表头数量。
单据引用使用流水显示号；单箱无-k，多箱按首次出现的去重扫描顺序编号。
例如A、A、B中B的引用为RK-xxxx-2，不按第3个输入槽编号。
事务号使用持久化UUID派生编号，不以记录总数+1生成；远端创建使用固定UUID请求标识。

四、校验和临时保护
整批先核实箱档案唯一、当前状态、原位置和目标仓映射，再持久化执行计划。
箱数量/版本、行归属或来源输入变化会停止执行，不用旧快照覆盖新数据。
当前入库只开放待入库且无位置；转仓只开放已跟踪位置中的完整来源批次。
半箱出库、零/负/缺失数量、不明旧位置等暂时拦截，等待对应业务口径或历史接管。
以上拦截是保护条件，不代表用户已经否决负责人旧系统中的其他分支。
读取失败、权限不足和接口超时不能当作“没有此箱”或业务异常。
本轮前置校验失败返回固定原因码，不自动回写飞书异常状态/原因；具体反馈映射另行完善。

五、执行顺序与恢复
先保存PREPARED计划及PLANNED逐箱事务，再进入RUNNING。
每个外部调用前提交步骤RUNNING意图，成功响应后保存远端记录ID，回读匹配后才CONFIRMED。
顺序为箱变更、对应事务账、出库明细，再核实全批结果及位置，最后更新流水处理状态和说明。
步骤不是跨表ACID事务；执行中可能已有部分远端变更，流水待处理不保证所有库存尚未变化。
遇到超时或错误，不删除已完成步骤、不盲目回滚；批次进入RECONCILE并保留同箱认领。
再调用同一execute只观察原步骤：
  已写成原计划目标值、或能唯一找回原事务号时，可核实后继续未开始步骤。
  UNKNOWN/RUNNING步骤仍是原值、事务号未找到、内容变化或出现重复事务时，继续待核账，不自动重发。
  已保存远端记录ID后，即使字段相同也不接受另一条替换记录作为原回执。
最终状态写成功但响应丢失时，可回读确认并收尾，不重复改箱、记账或延长冷却。
当前没有强制重置、跳过步骤、应用身份补写或自动重放不确定写入的接口。

六、位置和并发
PostgreSQL锁、同任务执行锁、owner_id及同箱唯一认领共同防止本系统内的并行覆盖。
IN/MOVE全批箱及事务确认后，目标位置才从RECORDED变OCCUPIED；转仓原位置进入10分钟冷却。
部分出库保留批次位置；全批箱均已出库且每箱出库事务核实后，才进入冷却。
重复确认保持首次冷却期限，不能因重复点击延长或提前结束。
旧位置预占和历史数据不在本轮自动接管，不按时间猜测UNKNOWN/RECORDED释放。
这些锁不能约束旧定时程序或人工直接改飞书；正式切换须确保库存主字段只有受控写入者。

七、数据库及排查
007_inventory_execution.sql新增3表，总计19表、7份迁移；原迁移不可改写。
inventory_executions：不可变批次计划、创建人、输入摘要、执行归属和批次状态。
inventory_steps：每次远端修改的意图、结果状态、远端ID和确认时间。
inventory_transactions：一箱一操作事务、原/目标位置、数量快照和账本回执。
QUEUED是接收状态，不等同于执行完成；write_requests.SUCCEEDED也只表示流水创建成功。
在项目目录运行：
  uv run python worker.py inspect executions --state RECONCILE
  uv run python worker.py inspect executions --record-id rec示例
  uv run python worker.py inspect execution --source-key "Base:扫码表:record_id"
这些命令只读PostgreSQL，不调用飞书、不解密令牌、不显示完整执行计划、不重发写入。
真实人员、扫码端和服务器持续运行验收按项目待办执行。测试用例、模拟数据和报告不随运行代码交付。

前置业务异常回写（2026-10-26）
整批业务校验失败且尚未建立库存执行计划时，向原扫码流水写回处理状态“异常”和处理说明。
处理说明包含已知异常原因及箱号；不向单选“原因”字段写自由文本，不新增飞书表或字段。
网络、权限、配置故障及执行中断不套用业务异常；数量、半箱、返库等未决口径继续保护拦截。
先持久记录回写意图，后调用飞书并回读核对；结果未知不自动重发，只允许回读确认。
确认异常回写且证明没有库存执行计划后，才释放本流水目标位置预占；转仓来源位置保持占用。
库存已开始执行的流水继续走原待核账恢复路径，不能被此功能改写为“整批未执行”。
后端新增inventory_rejections回执表和011_validation_feedback.sql迁移，合计22张表、11份迁移。
status查询只展示回执，没有写回或释放副作用；修正后新流水的关联规则仍待定。
本轮通过隔离PostgreSQL及模拟飞书验证，真实人员与飞书写回验收另行安排。

异常回执只读核账入口（2026-10-26）
在项目目录执行：.\.venv\Scripts\python.exe worker.py inspect rejections
按状态检查：.\.venv\Scripts\python.exe worker.py inspect rejections --state UNKNOWN
按飞书来源记录检查：.\.venv\Scripts\python.exe worker.py inspect rejections --record-id recXXXXX
可选--base-token、--app-id、--limit（1至100）、--before-id；默认按.env配置的应用过滤。
record-id是飞书内部记录ID，不是RK流水号。UUID倒序稳定分页，不代表发生时间排序；时间见created_at/updated_at。
有下一页时，将返回的next_before_id传给--before-id；翻页应沿用原筛选条件。
查询包含固定原因码、说明、回写状态和关联目标位置当前预占状态，不返回访问令牌或用户身份。
PENDING：已登记但尚未发送；RUNNING：已有发送意图；UNKNOWN：结果待核实；REJECTED：接口明确拒绝；CONFIRMED：曾回读确认回写。
CONFIRMED只代表历史核实成功，不证明当前飞书仍保持该值；remote_state_verified固定false。
该运维入口只查PostgreSQL，不连接飞书、不触发恢复、不重发、不释放任何位置，支持在数据库只读事务中执行。
人工核账先保存来源记录ID、回执ID、原因码和预占信息；再核对原扫码流水、箱档案、事务账与执行计划。
已有库存执行计划或部分库存变更时，使用inspect execution核查原执行计划，不能将其当成整批未执行重做。
未知结果且证据不齐时保持原回执和位置，禁止删除任务、手工改成成功或更换幂等键直接重试。
修正后新流水关联及人工解除未知占用尚待敲定，本命令不新增强制释放入口。
命令仅供具备服务器及数据库权限的运维人员使用，不作为普通员工绕过飞书可见范围的检索接口。
无需迁移，数据库仍22表、11迁移；配置不变，同步worker无需重启，新CLI进程立即读取新代码。
本轮隔离数据库及模拟飞书检查通过；正式表和Demo未写入，真实人员验收继续待办。
